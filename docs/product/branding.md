# Branding & Marks

## Name

**CYPHER**, capitalised, in body text and in the UI. `cypher` lowercase only in
identifiers, package names, CLI commands and URLs.

The name is not a claim about cryptography. Today the LAN transport is cleartext
HTTP and the audit says so plainly ([`../AUDIT.md`](../AUDIT.md) S-08). Calling a
product "Cypher" while it sends a permanent bearer token unencrypted is the kind
of gap that destroys trust when someone notices — and for this product category,
someone will.

**The name becomes accurate when roadmap P2-S1 (TLS + fingerprint pinning) and
P5-1 (Noise handshake) ship.** Until then, do not lean on cryptographic
implications in marketing copy. Describe what it does — local, private,
no-account — not what the name suggests.

## Logo and icon

`assets/icon/icon.png` in both Flutter apps. Currently a placeholder generated by
`flutter_launcher_icons`. A real mark is needed before a public launch, plus:

- Android adaptive icon (foreground + background layers, and a monochrome layer
  for Android 13+ themed icons)
- iOS AppIcon set (the scaffold exists under `mobile_app/ios/`)
- Windows `.ico` (present at `pc_app_flutter/windows/runner/resources/app_icon.ico`)
- Linux: PNG at multiple sizes + an `.svg` for the AppStream metadata
- A favicon and OG image for `website/`

Keep it legible at 24 px. It will mostly be seen in a tray, a taskbar and an app
drawer.

across `theme/colors.dart`, the desktop theme, the guest landing page and the

## Trademark and forks

Apache-2.0 grants copyright rights only. **It does not grant any right to use the
project name or marks** — this is explicit in Apache-2.0 §6, and it is restated in
[`../../NOTICE`](../../NOTICE).

So:

- Forks are welcome and encouraged. They **must rebrand.**
- Do not publish a fork as "CYPHER", "CYPHER Plus", "CYPHER Community Edition" or
  anything implying it is this project.
- Do not use the logo, icon or website design.
- Attribution in `NOTICE` must be preserved, per Apache-2.0 §4(d).

If someone wants to build a commercial product on this code, that is permitted by
the license — under their own name.

## Screenshots and demo assets

Before any public listing:

- Use a **clean demo machine** — no real file names, no real contacts, no
  identifiable desktop background, no personal browser tabs.
- Blur or replace anything identifying in both the desktop and phone captures.
- Show the light theme too, once P2-M2 ships it.
- A 30-second video of "phone picks a file → it lands on the PC" communicates the
  product better than any feature list. That single flow is the acquisition use
  case ([`features-and-applications.md`](features-and-applications.md) §2.1).
